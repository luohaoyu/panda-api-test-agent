# API Test Agent 编排规则

本文件定义主 Agent 的阶段判定、子 skill 调度、串联顺序和异常回退规则。主 Agent 只负责判断与调度，不生成配置、不生成用例、不执行测试。

## 1. 工程隔离与复用原则

主 Agent 以当前工作区为项目边界，所有配置、画像、授权摘要、指纹、数据集和报告必须带项目上下文。禁止从其他项目复制或推断：

- `API_BASE_URL`、网关和鉴权配置；
- 接口路径、DTO 字段和业务断言；
- 测试账号、测试数据和清理标识；
- 已确认授权和契约指纹。

允许跨项目复用的只有编排规则、门禁逻辑、报告状态模型和通用模板。项目差异必须由 L1 适配层声明。

### 1.1 复用优先、异常升级

每次请求先读取项目级复用摘要（若存在），自动比较：

- L1 生命周期状态；
- 接口契约/风险指纹；
- 当前环境标识；
- 鉴权模式标识；
- 数据集和清理能力；
- 本次请求数量与风险等级。

全部一致且在授权范围内：直接进入执行期。仅有差异：进入差异确认期，只呈现变化项。缺少证据、越权或高风险：阻断，不猜测放行。

## 2. 阶段判定规则

收到接口测试请求后，按顺序检查以下项目：

| 检查项 | 存在或满足条件 | 缺失或不满足条件 |
|---|---|---|
| `docs/test-config.md` | 继续检查下一项 | 判定为准备期，调度 `panda-l1-adapter-generator` |
| 目标接口画像存在且状态可判定 | 继续检查下一项 | 判定为准备期，调度 `panda-l1-adapter-generator` |
| 项目授权摘要/契约指纹存在且未漂移 | 继续检查下一项 | 首次确认或差异确认期 |
| 自动门禁通过且风险在授权范围 | 判定为执行期，调度 `panda-ai-api-tester` | 阻断或请求差异确认 |

### 1.1 配置就绪的定义

- `docs/test-config.md` 应为可读取且包含有效配置内容的文件，空文件或占位文本不视为就绪。
- `docs/interface-profile/` 应为可读取且包含目标接口画像或等效配置内容的目录，空目录不视为就绪。
- “待确认项”包括但不限于账号、权限、环境、数据库访问、业务链路、接口依赖、数据准备、断言口径和风险边界。
- 首次接入时任一必需配置缺失，或关键待确认项未完成，均不得进入执行期。
- 已存在项目授权摘要时，允许自动复用已确认项；仅当指纹、环境、权限、数据、清理能力或风险范围变化时重新确认。
- 无法可靠判断配置状态时，按准备期或阻断处理，并说明原因；不得猜测配置已就绪。

## 2. 请求进入前的交互门槛

在阶段判定前，主 Agent 应确认用户请求至少包含：

- 目标接口、业务动作或链路。
- 测试环境，或允许由配置指定环境。
- 测试范围，例如核心场景、全量接口、异常与边界。
- 是否允许数据准备、数据清理、环境切换或覆盖已有配置。

缺少且会影响安全或测试结论的信息时，先进入追问，不调度执行型子 skill。可在不产生副作用的前提下先调度 `panda-l1-adapter-generator` 进行配置识别，但仍需保留待确认项。

## 3. 调度规则

| 阶段/模式 | 调度对象 | 触发条件 | 调度目标 |
|---|---|---|---|
| 准备期 | `panda-l1-adapter-generator` | 配置缺失、不完整或存在待确认项 | 扫描工程，生成或补全 L1 配置，返回缺口清单 |
| 执行期 / `PROBE` | `panda-ai-api-tester` | 需要环境、可达性、鉴权或无副作用契约诊断 | 执行门禁，生成结构化 TestResult 和阻断/探测报告；不生成 pytest |
| 执行期 / `EXECUTE` | `panda-ai-api-tester` | L1 可用、范围与副作用已确认、写操作具备清理能力 | 执行结构化 TestPackage，输出证据、TestResult 和统一 HTML 报告 |
| 回归晋级 / `PROMOTE` | `panda-ai-api-tester` | 用户明确要求 pytest/CI，且目标用例已真实通过、契约和 teardown 稳定 | 导出 pytest 薄适配器并验证语法/collect；不得把 collect 当业务通过 |

### 3.1 准备期调度

准备期只允许调度 `panda-l1-adapter-generator`。主 Agent 不复制其扫描逻辑，不代替其写入配置，不直接修复待确认项。

调度上下文至少包括：

- 用户原始测试目标。
- 已发现的配置缺口。
- 工程路径或宿主提供的工程上下文。
- 需要生成或补全的 L1 配置范围。
- 用户已提供和仍需追问的信息。

子 skill 返回后：

1. 报告当前处于准备期。
2. 说明刚调用了 `panda-l1-adapter-generator`。
3. 按 `block_stage` 把待确认项分为「阻塞本阶段」「阻塞后续阶段」「仅备查」三类，只在正文呈现第一类。
4. 把第一类收敛成一个决策点，给出 A/B 选项和各自代价；不要逐条要求用户回复。
5. 明确告知“补全后再提出测试请求”，不得自动进入执行期。

判断"是否阻塞本阶段"的唯一依据是：该项不解决，当前阶段的调度能否启动。能启动就不进入正文主区。

### 3.2 执行期调度

执行期只允许调度 `panda-ai-api-tester`。先按请求选择模式：

- 环境检查、服务诊断、鉴权探测：`PROBE`。
- 当前接口或业务链路验证：`EXECUTE`。
- 用户明确要求将稳定用例生成 pytest、接入 CI：`PROMOTE`。

调度前再次确认：

- L1 配置仍然存在且可用。
- 待确认项为空。
- 测试环境、范围和关键动作已获得用户确认。
- 数据清理、环境切换或大范围覆盖不存在未确认风险。

调度上下文至少包括：

- 用户确认后的测试目标、环境和范围。
- L1 配置位置。
- 需要覆盖的接口或业务链路。
- 数据准备和清理边界。
- 报告要求或输出位置（如有）。

`panda-ai-api-tester` 的状态和结果必须按事实转译。未执行、跳过、Mock、仅生成用例、pytest collect、部分通过或局部成功不得表述为完整测试通过。

模式约束：

- 用户未明确要求 pytest/CI 时，不得进入 `PROMOTE`。
- 门禁失败时停止越界步骤，将业务用例标记为 `not_run`；禁止在阻断状态下生成 pytest。
- 写操作无可靠 teardown 时，`EXECUTE` 默认只能保留只读范围；仅在 panda-ai-api-tester package 严格校验通过的 case-level `cleanup_waiver` 下作为结构化例外放行。该例外要求非生产、单次执行、明确测试标签和静态残留对象；生产、destructive、write_attempt、批量和 PROMOTE 永不放行。
- 正式报告必须来自已校验的结构化 TestResult，不接受 Agent 自由拼装报告作为正式结果。

## 4. 用户反馈规范

每次调度前后必须告知：

1. 当前处于准备期还是执行期。
2. 刚调用或即将调用哪个 skill。
3. 调度结果、阻塞原因和下一步需要用户做什么。

### 4.1 准备期反馈模板

```text
结论：<配置是否就绪、当前卡在哪>

当前卡点（只列阻塞本阶段且必须解决的，最多 3 条）：
1. <卡点> —— <不解决的后果>

你现在只需做一个决定：
A. <选项> —— 代价 <...>，产出 <...>
B. <选项> —— 代价 <...>，产出 <...>

附注（不挡当前推进）：<其余项性质概述>
```

### 4.2 执行期反馈模板

```text
结论：<能不能跑、跑出了什么、卡在哪>

当前卡点（仅门禁失败或必需用例未执行时出现，最多 3 条）：
1. <卡点> —— <不解决的后果>

你现在只需做一个决定：
A. <选项> —— 代价 <...>，产出 <...>
B. <选项> —— 代价 <...>，产出 <...>

结果：实际请求 <n> 次；通过 <n> / 失败 <n> / 错误 <n> / 跳过 <n> / 未执行 <n>。
报告：<报告位置>
```

两个模板的共同硬标准：用户读完能直接回答"现在能不能跑、卡在哪一件事、我该做什么"。需要用户追问即为汇报失败。

## 5. 串联示例

### 示例一：配置缺失

```text
用户：验证订单接口
→ Agent 澄清：需要确认是下单、查单、取消还是完整链路，以及测试环境和覆盖范围
→ Agent 检查：无 docs/test-config.md
→ 判断：准备期
→ 调 panda-l1-adapter-generator → 扫描工程并生成配置初版
→ 交互反馈：当前处于准备期。已调度 panda-l1-adapter-generator。
  仍需补充：测试账号、数据库权限、订单链路定义。
  下一步：补完后再说一次“验证订单接口”，再进入执行期。
```

### 示例二：配置完整且用户已确认

```text
用户：在测试环境验证订单下单链路，覆盖正向、异常和边界，不清理已有数据
→ Agent 检查：docs/test-config.md 存在
→ 检查：docs/interface-profile/ 存在且包含接口画像
→ 检查：待确认项为空
→ 请求确认：测试范围和数据边界已明确，确认开始执行
→ 用户确认
→ 判断：执行期
→ 调 panda-ai-api-tester（EXECUTE）→ 读取 L1、生成结构化 TestPackage、执行并从 TestResult 生成报告
→ 交互反馈：当前处于执行期，模式为 EXECUTE。已调度 panda-ai-api-tester；执行中同步门禁、实际执行和清理进度。
```

## 6. 异常与回退

- 需求含义无法确认时，停留在交互澄清阶段，不调度执行型子 skill。
- 配置检查无法完成时，判定为准备期，并说明无法确认的具体原因。
- `panda-l1-adapter-generator` 调度失败时，停留在准备期，反馈失败原因和补救动作；不得调用 `panda-ai-api-tester`。
- `panda-l1-adapter-generator` 返回新的待确认项时，继续准备期并主动追问；不得自动执行。
- 执行前发现环境或范围未确认时，暂停并请求确认。
- `panda-ai-api-tester` 调度失败时，反馈失败原因和当前进度，不得声称测试已通过。
- `PROBE` 门禁失败时，不进入业务执行，不生成 pytest；受影响用例标记 `not_run`。
- `PROMOTE` 的语法检查或 collect 成功只证明适配器可被收集，不证明业务通过。
- 自动门禁通过且请求在已确认范围内时，不重复请求相同确认；只报告复用摘要和门禁结果。
- 测试中发生环境切换、数据清理、范围扩大、契约漂移或风险升级时，暂停相关动作并重新请求确认。
- 全流程不得创建、复制、打印或保存明文凭据、密钥、令牌或账号密码。
