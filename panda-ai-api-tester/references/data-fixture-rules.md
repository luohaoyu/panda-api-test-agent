# DB/Redis 造数、断言与清理规范

## 造数

- 所有测试数据写入时带 `tag=TEST`，并记录本次运行唯一 run id。
- Redis key 统一增加 `test:` 前缀，例如 `test:order:{order_id}`。
- 造数结果返回可清理的主键、key 和运行标识；不得依赖模糊条件删除。
- DB 连接仅允许指向测试库，连接信息从 `.env` 或安全环境变量读取。

## 落库与一致性断言

- 落库断言通过主键或本次运行标识查询表，验证状态、关联关系和关键业务值。
- 一致性断言按 DB 与 Redis 的同一业务主键比对关键字段。
- Redis 写入、过期或删除存在 TTL 延迟；校验应采用配置的短暂重试窗口，不将可解释的 TTL 延迟直接判为缺陷。
- 经过重试窗口仍不一致时，报告实际 DB 值、缓存值、TTL 和时间戳。

## 清理

- 每个产生写副作用的用例和 HTTP fixture 优先配置 teardown；普通非生产单次业务写入在无法提供 teardown 时可采用可审计的残留登记或满足 TestPackage 规范的 case-level `cleanup_waiver`。Runner 在写请求获得响应后立即登记清理或残留对象，无论后续断言通过、失败或异常，都执行对应处置；豁免用例不注册 teardown，必须登记风险接受的残留对象。
- 写请求使用 `cleanup_extract` 提取精确主键或 key；普通 `extract` 只在断言通过后供业务 DAG 使用，二者不得混淆。
- teardown 只删除本次运行通过精确对象引用登记的 `tag=TEST` 数据和 `test:` 前缀 key。
- 清理失败不能静默；报告标记清理失败并保留待处理对象清单。
- 不删除非本次运行、无 TEST 标识或无 test 前缀的数据。

## 安全与降级

- 只连测试库；禁止生产连接串和真实凭据进入模板、日志或报告。
- `ENABLE_DB_ASSERT=false` 时，DB 校验优雅降级为明确的“未启用”，不是通过；API 层三重断言仍必须执行。
- Redis 未启用时，不生成缓存一致性通过结论；连接失败时报告为环境问题。
- DB/Redis 初始化失败给出清晰错误，禁止 silent pass、无条件 skip 或 mock 数据源。
