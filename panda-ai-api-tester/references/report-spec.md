# HTML 报告规范

## 生成原则

正式报告必须由 `scripts/render_report.py` 从通过 `scripts/validate_result.py` 校验的 `result.json` 确定性生成。禁止由 Agent 根据对话或控制台输出自由组装正式 HTML。

pytest 只在 `PROMOTE` 模式作为可选执行适配器。pytest-html 产物可作为附加证据，但不能替代统一 TestResult 报告。

## 必须展示

- 项目、需求、运行 ID、模式和目标环境。
- 门禁结果，与业务用例统计分开展示。
- 用例总数、实际执行数、通过、失败、错误、跳过、未执行数量。
- 每条用例的接口/场景、预期、实际、状态、分类、阻塞来源和证据引用。
- “需求点 → 业务规则 → 测试场景 → 用例 → 关键断言 → 证据 → 结论”的覆盖矩阵；需求或规则未覆盖、未执行时不得显示通过。
- 全局执行过程入口，展示测试包校验、门禁、夹具、业务用例、teardown 和最终 verdict 的确定性顺序。
- 每条用例的执行过程入口，展示请求变量解析、清理预登记、脱敏 HTTP exchange、变量提取、断言和完成/阻断状态。
- 每条已执行用例的结构化断言明细，至少展示稳定断言 ID、断言类型、运算符、预期、实际和状态。
- 运行时门禁、业务用例和 teardown 的证据引用；相对链接必须可从报告所在目录直接打开。
- verdict、清理状态、清理动作、待清理对象和已知覆盖缺口；存在豁免时必须明确展示“已风险豁免”，列出豁免编号、原因、残余风险、审批者、有效期、标签和残留对象，不能显示为清理通过。
- 执行开始、结束、持续时间和报告生成时间。

## 视觉与交互

- 首屏优先展示最终 verdict、运行标识和核心指标，不把门禁数量混入业务用例通过率。
- 使用统一状态色与文字标签双重表达，不得仅依赖颜色区分结果。
- 业务用例使用可展开详情承载断言与证据，保证摘要可扫读、详情可追溯。
- 页面必须支持窄屏自适应和浏览器打印，禁止依赖外部 CDN、远程字体或前端脚本才能阅读。
- `executed=0` 时通过率显示“不计算”，进度条不暗示通过或失败。

## 通过率

仅当 `executed > 0` 时展示执行通过率：

```text
passed / executed
```

`skipped` 和 `not_run` 不进入分母。`executed=0` 时显示“不计算”，禁止展示 0% 或 100% 造成误导。

## 失败分类

- `environment`：DNS、连接拒绝、超时、服务依赖、DB/Redis 不可用。
- `test_case`：画像、数据、断言、变量提取或清理逻辑错误。
- `product_defect`：环境、用例和数据有效，服务可复现地违反契约。
- `inconclusive`：证据不足。

## 证据与安全

报告只展示脱敏 URL、请求摘要和响应摘要。token、cookie、密码、连接串和敏感业务值不得出现。详细证据通过相对引用指向当前运行的 `evidence/`，不得引用其他项目运行结果作为当前证据。

## 报告失败

结果校验失败或报告写入失败时，本次运行不得标记为完整通过。修复结构化结果后重新生成，不允许手工修改 HTML 掩盖模型错误。
